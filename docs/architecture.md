# 서비스 아키텍처 (로컬 우선 + 세무사 검토)

상태: 개정 2판 · 2026-09-30
이전 판(2026-09-29, 서버 저장 방식)을 대체한다. 변경 이유는 §9.

## 1. 한 줄 요약

**계산은 사용자 기기에서 한다.** IT 법인 서버는 앱 코드와 공개 시세만 제공하고 사용자 재산 정보를 보지 않는다.
사용자가 **세무사 검토**를 선택한 경우에만, 데이터를 **사무소 공개키로 암호화해** 사무소로 보낸다.

## 2. 서비스 단계와 책임 주체

사용자가 셀프 도구와 세무사 검토 중에서 고른다.

| 단계 | 주체 | 하는 일 | 데이터 위치 |
|---|---|---|---|
| 1. 셀프 도구 | IT 법인 | 지갑·거래소 연결, 원장·분류·세액 계산, 연말 보유 기록 | 사용자 기기만 |
| 2. 셀프 신고 | IT 법인 | 신고서 데이터·초안 생성. **제출은 사용자가 본인 인증으로 직접** | 사용자 기기만 |
| 3. 세무사 검토·신고 | 세무사 사무소 | 검토 대기열 처리, 분류 확정, 세무대리인으로 신고 | 사무소 (사무소 공개키로 암호화해 전달) |

- IT 법인: 앱 개발·운영, 1·2단계 요금(정액제). **세무 상담·판단을 하지 않는다.** 고객지원은 제품 사용 문의까지만 받고, 세무 질문은 3단계로 안내한다. AI 도우미를 넣는다면 개별 거래의 세무 판단을 하지 않도록 범위를 제한한다.
- 사무소: 3단계에서 **별도 수임 계약**을 맺고 보수도 사무소 명의로 받는다. IT 법인이 보수를 대신 받지 않는다.
- IT 법인 설립 전까지는 개발만 진행한다. 결제·약관은 법인 설립 후 설계한다.

## 3. 전체 구조

```
[사용자 기기 · 브라우저]
  ├─ 수집: 지갑(블록체인 직접 조회), 거래소(API 키 또는 CSV)
  ├─ 원장 · 대사 · 분류 · 세액 엔진 · 신고서 초안
  ├─ 저장: IndexedDB (API Secret은 사용자 비밀번호로 암호화)
  └─ (선택) 암호화 백업·동기화 → 서버에는 암호문만
        │
        │ 공개 데이터만 요청 (시세 · 앱 코드)
        ▼
[IT 법인 서버]
  ├─ 앱 배포
  ├─ 시세 API (날짜 단위 번들, §6)
  ├─ 거래소 API 중계 (서명된 요청만 전달, Secret은 받지 않음)
  ├─ 계정 · 결제 · 암호화된 백업 보관 (내용을 볼 수 없음)
  └─ 3단계 전송 중계 (사무소 공개키로 암호화된 묶음만 통과)
        │
        ▼
[세무사 사무소]
  ├─ 사무소 개인키로 복호화 (사무소 기기에서만)
  ├─ 검토 대기열 · 검토 로그 · 완전성 확인 · 수임 수락/거절
  └─ 신고 (세무대리인)
```

## 4. 데이터 수집

### 지갑
- 블록체인에서 직접 조회한다 (EVM: Blockscout, BTC: Esplora). 요청은 **사용자 기기에서** 나가므로 서버 IP가 차단될 일이 없다.
- 조회 서버를 사용자가 바꿀 수 있다 (자기 노드, 다른 공개 서버). BTC는 이미 지원, EVM은 추가 예정.

### 거래소: 두 가지 방식을 모두 둔다

| 방식 | 장점 | 단점 |
|---|---|---|
| **API 키 (브라우저 전용)** | 한 번 연결하면 자동 동기화 | 키를 입력해야 함. Secret은 기기에만 저장하고 서명도 기기에서 함. 서버 중계는 서명된 요청만 봄 |
| **CSV 업로드** | 키를 줄 필요 없음 | 새 거래가 생기면 다시 올려야 함 |

### CSV 표준화
표준 형식은 **원장(`LedgerEntry`)** 하나다. 거래소 CSV마다 **변환기(어댑터)**를 두어 원장으로 바꾼다.

```
거래소 CSV ─▶ 형식 자동 인식 (열 이름) ─▶ 해당 버전 변환기 ─▶ 원장 ─▶ 분류 ─▶ 세액
처음 보는 CSV ─▶ 열 연결 화면 (날짜·코인·수량·가격·수수료 지정) ─▶ 원장
```

- 변환기는 `{ 거래소, 형식 버전, 열 이름 서명, 행 → 원장 항목 변환 }`으로 등록한다. 거래소가 형식을 바꾸면 새 버전을 추가한다.
- 거래소별 용어(Buy/Sell/Fee/Deposit/Convert/Earn 등), 수수료 표기, 시간대(UTC/KST)를 변환기 안에서 처리한다.
- 실제 샘플 파일(개인정보 제거)로 변환기마다 테스트를 둔다.
- 우선순위: 사용자가 많은 거래소부터 (세무사 목록 대기).
- 최후 수단: 표준 CSV 양식을 내려받아 채워 올리기.

### 연말 보유 기록 (2026-12-31)
서버가 키를 갖지 않으므로 서버 자동 기록은 하지 않는다.
- 지갑: 블록체인 기록으로 **나중에 언제든 복원** 가능.
- 거래소: 연말 전후 앱에서 "지금 기록하세요" 안내. 놓친 경우 1월 중 CSV나 바이낸스 30일 스냅샷 API로 12/31 잔고를 받는다.

## 5. 3단계 전송 (세무사 검토 선택 시)

1. 사용자에게 **무엇을 누구에게 보내는지** 보여 주고 명시적으로 동의를 받는다 (계정 목록, 기간, 사무소 이름).
2. **완전성 확인서**: 모든 지갑·거래소 계정을 연결했는지 사용자가 확인·서명한다.
3. 데이터 묶음을 새 대칭키로 암호화하고, 그 키를 **사무소 공개키**로 암호화한다 (하이브리드 암호화).
4. IT 법인 서버는 암호문만 중계·보관한다. 복호화는 사무소 기기에서만 한다.
5. 사무소 직원이 여러 명이면 각 직원 공개키로 대칭키를 따로 암호화한다.

## 6. 시세

- 사용자가 어떤 코인을 언제 거래했는지 서버에 드러나지 않도록 요청 단위를 넓힌다.
- **일별 번들**: 주요 코인의 일별 시세를 통째로 내려받는다 (의제취득가, 잔고 평가).
- **1분 시세**: 필요한 날짜의 해당 코인 하루치를 요청한다. 정확한 거래 시각은 보내지 않는다.
- 평가 기준은 docs/classification.md §6-1 (세무사 잠정 기준 포함).

## 7. 세무사 검토 대기열

"명의만 빌려주는 구조가 아니다"는 것을 보여 주는 **실질 검토의 증거**로 설계한다.

- **필터**: 자동 분류 중 확신도가 낮거나 해석이 애매한 유형만 올린다 (추정·검토 필요 상태, 에어드랍·스테이킹 보상·LP 토큰·브릿지·래핑).
- **검토 로그**: 건마다 세무사의 판단과 근거를 남긴다 (수정 불가).
- **완전성 확인서**: 수임 전에 전체 지갑·계정 목록을 사용자에게 확인받는다.
- **용량 제한**: 처리 가능한 건수를 넘으면 신규 접수를 막는다.
- **수임 거절**: 자료가 불충분하거나 의심스러우면 거절할 수 있다.

## 8. 신뢰

- 앱이 어떤 서버에 무엇을 요청했는지 사용자가 볼 수 있는 **네트워크 요청 내역 화면**.
- 오픈소스 공개와 재현 가능한 빌드는 사업 판단 후 결정.
